# Vapi Custom LLM Server (Google Gemini Bridge)

This repository contains the implementation for **Option 1: Custom model server + Vapi function calls** to connect Google Gemini (the LLM power behind Google's speech pipeline) to your Vapi voice assistant.

Additionally, this document explains how to use Google Gemini **natively** inside Vapi without maintaining your own bridge server.

---

## Architecture Overview (Option 1: Custom Bridge Server)

```
[ Caller ] <---(Audio Stream)---> [ Vapi Voice Bot ]
                                          |
                                    (HTTP POST/SSE)
                                          |
                                          v
                                [ Your Bridge Server ]
                                (translates format & roles)
                                          |
                                    (Google SDK)
                                          v
                                 [ Google Gemini API ]
```

When Vapi acts as the voice orchestrator:
1. It listens to the user and converts the voice stream to text.
2. It sends the OpenAI-compatible request payload to your server at `/chat/completions`.
3. Your server translates the chat history to the strict format required by the Google Gen AI API and retrieves the response.
4. Your server streams text chunks back to Vapi in real time.
5. Vapi speaks the stream back to the caller using a text-to-speech engine (TTS).

## ⚡ Quick Start (Native Alternative)

If you don't want to host your own server at all, Vapi natively supports Gemini 2.0/3.x. You can configure your assistant directly via the SDK/API or Dashboard by setting:
- **Model Provider:** `google`
- **Model:** `gemini-2.0-flash-realtime-exp` (or the latest Flash models)

This connects Vapi directly to Google's real-time multimodal engine.

## 🛠️ Step-by-Step Setup (Option 1 Bridge Server)

### 1. Install Dependencies
Run this in the repository folder:
```bash
npm install
```

### 2. Configure Environment Variables
Open the `.env` file and replace the placeholders with your credentials:
```env
PORT=4000
GEMINI_API_KEY=your_google_gemini_api_key
GEMINI_MODEL=gemini-1.5-flash
VAPI_API_KEY=your_vapi_api_key
SERVER_URL=https://your-ngrok-or-tunnel-url.ngrok-free.app
```

### 3. Expose Your Local Server (Using Ngrok)
To allow Vapi to talk to your local server, expose port `4000` using ngrok:
```bash
ngrok http 4000
```
Copy the forwarding URL (it should start with `https://`) and paste it into the `SERVER_URL` variable in your `.env` file.

### 4. Run the Server
Start your local bridge server:
```bash
node server.js
```

### 5. Create Your Vapi Assistant
In a new terminal window, execute the assistant creation script:
```bash
node create-assistant.js
```
This script will make an API call to Vapi using your Vapi key to register an assistant configured to point to your new bridge server's `/chat/completions` endpoint.

## 🎙️ Setup Google Custom TTS (Text-to-Speech)

If you want the assistant's voice to be dynamically generated by Google Cloud's premium Text-to-Speech API (such as the high-quality Neural2 or Journey voices), the bridge server supports a custom `/tts` route that streams raw PCM audio back to Vapi.

### 1. Enable Google Cloud Text-to-Speech API
1. Go to the [Google Cloud Console](https://console.cloud.google.com/).
2. Enable the **Text-to-Speech API** for your project.

### 2. Create Service Account Credentials
Because Google Cloud TTS does not support standard API keys (it requires OAuth 2.0 or Service Account IAM authentication):
1. Go to **IAM & Admin > Service Accounts** in the Google Cloud Console.
2. Create a service account and assign it the **Text-to-Speech User** role.
3. Click on the service account, go to the **Keys** tab, and select **Add Key > Create New Key** (JSON format).
4. Save the downloaded file into the root folder of this project with the name **`google-credentials.json`**.
   *(The server will automatically detect and load this file on startup!)*

### 3. Register or Update the Assistant
Run the assistant registration script again:
```bash
node create-assistant.js
```
This registers an assistant configured to use the custom voice:
* **Voice Provider:** `custom-voice`
* **Voice ID:** `en-US-Journey-F` (or any other Google TTS voice name)
* **Server URL:** Your public ngrok tunnel `/tts` endpoint.

When a call is initiated:
1. Vapi gets text tokens from the Gemini bridge.
2. Vapi sends a request containing the text to your `/tts` endpoint.
3. Your server calls the Google Cloud TTS API, retrieves the audio WAV file, strips the 44-byte WAV header, and streams the raw line-16 PCM back to Vapi for low-latency voice output!
